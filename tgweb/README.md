# WEB-прокси Telegram (tgweb)

Деплой серверной части **нового типа прокси Telegram** — «WEB proxy»
(представлен в августе 2026, первый клиент с поддержкой — Telegram Desktop 7.1).
Управление добавленными серверами — через бота (`/addtgweb`, `/tgweb`)
или веб-админку (кнопка «WEB-прокси» на странице нод).

## Что это такое

Обычный MTProxy-трафик легко детектируется и режется провайдером. WEB-прокси
упаковывает его в обычный HTTPS/WebSocket: клиент Telegram держит WebView-транспорт,
который выглядит как браузерная сессия на обычном сайте. На сервере релей
`telegramdesktop/tproxy-server` разделяет мультиплексированные потоки и отдаёт
их официальному MTProxy. Для провайдера это HTTPS-трафик на «обычный» сайт.

Клиент настраивается двумя значениями: **домен** и **секрет**. Порт всегда 443.

## Важно: где это работает

WEB-прокси **не деплоится на Railway** — и вот почему:

| Требование tproxy-server | Railway |
|---|---|
| Публичный IPv4 + свои порты 80/443 (ACME-сертификат Caddy) | TLS терминируется на краю Railway, своего сертификата нет |
| MTProxy должен видеть свой публичный адрес (иначе middle-end соединения молча рвутся) | Контейнеры за NAT-балансиром |
| Домен, указывающий на сервер | TCP-прокси на случайных портах `*.rlwy.net` |

Поэтому WEB-прокси ставится на **VPS** (Ubuntu 22.04+/Debian 12+, x86_64,
минимум 1 vCPU / 1 GB). Управлять им всё равно удобно из бота на Railway.

## Состав бандла

```
tgweb/
├── docker-compose.yml      # caddy + tproxy + mtproxy
├── Caddyfile               # HTTPS на 80/443, все пути -> релей
├── Dockerfile.tproxy       # сборка официального релея (закреплённый коммит)
├── Dockerfile.mtproxy      # официальный MTProxy (коммит из install.sh)
├── tproxy-entrypoint.sh    # рендер config.json / profiles.json из .env
├── mtproxy-entrypoint.sh   # подтягивает конфиги Telegram DC, NAT-режим
├── site/index.html         # публичный сайт-прикрытие (замените на свой!)
├── .env.example            # шаблон настроек
└── setup.sh                # проверки DNS + docker compose up
```

## Установка за 5 шагов

**1. DNS.** A-запись вашего домена -> публичный IPv4 VPS:

```
tg1.example.com.   A   203.0.113.7
```

**2. Файрвол провайдера:** открыть TCP 22, 80, 443. Порты 2398/8080/8081
наружу не открываются (в compose они и так не публикуются).

**3. Секрет:**

```bash
openssl rand -hex 16
```

**4. Запуск:**

```bash
cd tgweb
cp .env.example .env
nano .env          # WEB_HOSTNAME, WEB_SECRET, ACME_EMAIL
sudo ./setup.sh
```

`setup.sh` проверит DNS и секрет, соберёт три контейнера и выдаст готовую ссылку.

**5. Добавить в менеджер** (бот на Railway):

```
/addtgweb web1|tg1.example.com|ваш_секрет_32_hex
```

и раздавать ссылки `/tgweb`, либо копировать их в веб-админке на странице «Ноды».

## Проверка, что всё живо

```bash
docker compose ps
curl -fsS https://ваш.домен/                       # сайт отвечает
curl -fsS http://127.0.0.1:8081/healthz            # релей здоров
docker compose logs mtproxy | grep -c 'Disconnected from RPC Middle-End'
# должно быть 0 или почти 0; если растёт поток — вы за NAT, см. ниже
```

## Если сервер за NAT (типично для облачных VPS)

MTProxy строит middle-end сессию с Telegram DC, выводя ключи из собственного
адреса. За 1:1 NAT адрес «свой», а Telegram видит другой — соединения молча
рвутся сразу после рукопожатия, и прокси «висит» без ошибок в логах релея.

Лечится переменной в `.env`:

```
MTPROXY_NAT_INFO=10.0.0.5:203.0.113.7
```

(внутренний IP сервера:публичный IP), затем `docker compose up -d`.

## Один домен — один релей

Один процесс релея обслуживает один публичный домен. Второй WEB-прокси =
второй VPS и второй домен (например `tg2.example.com`). Для разных серверов
используйте **разные** секреты.

## Замена сайта-прикрытия

Сайт в `site/` — заглушка. Замените `index.html` на реальный контент (о проекте,
контакты, блог — что угодно статическое). Уникальный сайт усложняет активное
зондирование прокси. После замены: `docker compose restart tproxy`
(сайт читается один раз при старте).

## Ограничения текущих клиентов

- Работает в Telegram Desktop 7.1+ (и PoC-клиентах Android/iOS на ветках разработки).
- Ссылки `https://t.me/webproxy?...` фронтенд t.me пока не регистрирует —
  если ссылка не открылась, используйте форму `tg://webproxy?...` (бот отдаёт обе)
  или введите домен и секрет вручную: Настройки → Данные и память → Прокси.
